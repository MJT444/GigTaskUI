# GigTask database handover note (draft)

Source reviewed: [MohitSharma25/GitTask](https://github.com/MohitSharma25/GitTask), commit `5d38fee`. This is a **static code review**.

## What is present and appears usable

PostgreSQL scripts define clients, freelancers, contracts, escrow audit logging, a `fund_gig` procedure, a partial unique index, revenue analytics, and a freelancer statistics materialized view. MongoDB scripts define portfolios, gig reviews, worker-location pings, a geospatial search, and faceted review analytics. The MongoDB seeder reads freelancer UUIDs from PostgreSQL, giving those collections an explicit cross-database identifier. The README gives a setup order and the repository includes performance captures. These are source findings, not runtime verification.

**Transaction/constraint mismatch:** The [partial unique index](https://github.com/MohitSharma25/GitTask/blob/5d38fee0356435ccf7a018d306fa8978b8b6a9ab/sql/02_indexes.sql#L1) applies only to `IN_PROGRESS` contracts, while [`fund_gig`](https://github.com/MohitSharma25/GitTask/blob/5d38fee0356435ccf7a018d306fa8978b8b6a9ab/sql/04_stored_procedures.sql#L24) creates `FUNDED` contracts. A second funding call for the same freelancer will not trigger that index, even though the assignment expects an active-contract failure to be demonstrated. The current schema can demonstrate the constraint by advancing one contract to `IN_PROGRESS` and trying to advance another for the same freelancer. If the failure must occur during funding, the database rule and seed data need a coordinated change.
